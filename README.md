# 🚀 Gulp + TypeScript Professional Engine (v5.0 - Ultimate Edition)

Современный, сверхбыстрый и полностью автоматизированный кастомный движок для профессиональной модульной веб-разработки. Построен на строгом компонентном подходе (БЭМ-компоненты как изолированные экосистемы «Plug and Play») с использованием Gulp 5, Webpack 5, строгого TypeScript и плоской конфигурации ESLint v10.

---

## 🛠️ Быстрый старт (Развертывание и Разработка)

Чтобы запустить проект или развернуть окружение, выполните следующие команды в терминале:

1. **Установите зависимости** через стабильное зеркало с автоматическим разрешением конфликтов peer-зависимостей линтера:

   ```bash
   npm install --registry=https://npmmirror.com --legacy-peer-deps
   ```

2. **Инициализируйте структуру папок** (Header-Main-Footer):

   ```bash
   npm run init
   ```

3. **Запустите сервер разработки** (с вотчерами и автооткрытием браузера):
   ```bash
   npm run dev
   ```

## 🧱 Встроенный CLI-конструктор компонентов

Забудьте про ручное создание файлов и прописывание импортов — используйте автоматизацию:

- **Создать БЛОК (компонент страницы):**

  ```bash
  npm run create -- имя_блока
  ```

  Генерирует HTML/SCSS/TS в `src/components/` и жёстко подключает в точки входа. Идеал для каркаса сайта (например: `header`, `hero`).

- **Создать МОДУЛЬ (в ленивом асинхронном режиме):**

  ```bash
  npm run module -- имя_модуля
  ```

  Генерирует SCSS/TS в `src/js/modules/` и подключает в `app.ts` через динамический `import()`. Код подгрузится только при наличии элемента с соответствующим классом на странице. Идеал для тяжелой логики (`slider`, `tabs`).

- **Создать ПЛАГИН (расширение функционала):**

  ```bash
  npm run plugin -- имя_плагина
  ```

  Генерирует SCSS/TS в структуре `src/js/plugins/` и подключает в `app.ts`. Идеал для кастомных библиотек (`form-validator`).

- **Универсальное УДАЛЕНИЕ:**
  ```bash
  npm run remove -- имя_элемента
  ```
  Универсальный деструктор. Физически удаляет папки и полностью вырезает регулярные выражения импортов и вызовов. Снабжён массивом `PROTECTED_NAMES` для защиты системных директорий от случайного стирания.

## 🎯 Gulp-команды прямого вызова

Для продвинутых пользователей доступны изолированные Gulp-задачи напрямую:

- `npx gulp` — Запуск задачи по умолчанию (разработка).
- `npx gulp build` — Финальная сборка проекта.
- `npx gulp styles` — Точечная компиляция и оптимизация стилей в `app.min.css`.
- `npx gulp scripts` — Изолированная сборка и бандлинг скриптов в `app.min.js`.
- `npx gulp html` — Сборка HTML-страниц и шаблонов.
- `npx gulp images` / `npx gulp createWebp` / `npx gulp sprite` — Раздельное управление графикой.
- `npx gulp fonts` / `npx gulp fontsStyle` — Изолированный перенос и генерация стилей шрифтов.
- `npx gulp cleandist` — Полная очистка папки `dist`.
- `npx gulp help` — Вывод справочной информации о доступных задачах проекта.

## 🔥 Улучшенные технологические особенности v5.0

### 💎 Качество кода, Надежность и Безопасность

- **Сквозное интеграционное тестирование (Vitest + JSDOM):** В движок интегрирована современная промышленная матрица из **21 теста**. Проверяется всё: от DOM-событий UI-компонентов (модалки, контакты) до валидности выходных бандлов HTML, CSS, JS, графических WebP и шрифтовых пайплайнов.
- **Интеграция с Telegram API:** Форма контактов полностью функциональна. Сообщения отправляются напрямую в Telegram через защищенный механизм. Ключи доступа (`TOKEN`, `CHAT_ID`) хранятся в `.env` и автоматически инжектируются в проект при сборке через кастомный Gulp-генератор `env-config.js`.
- **TypeScript Strict & Webpack 5:** Полная поддержка компиляции, строгая проверка типов (`strict: true`) и изоляция модулей для бесперебойной работы.
- **Modern ESLint & Stylelint:** Автоисправление (`--fix`) измененного файла происходит прямо при сохранении. CSS-свойства строго сортируются по логическим группам (Recess-порядок).
- **Защитный щит (Husky + Блокировка деплоя):** При каждой команде `git commit` система автоматически запускает тесты за доли секунды. Если тесты упали или линтер нашёл ошибку — коммит блокируется. Аналогичный барьер встроен в деплой: сломанный бандл никогда не попадёт на хостинг.
- **Умная защита авторских прав:** Интеллектуальный скрипт полностью блокирует вызов контекстного меню, клавишу F12, а также комбинации Ctrl+U (просмотр кода) и Ctrl+S (скачивание сайта). На локальном сервере (`localhost`) защита автоматически отключается для удобства дебага.

### 🖼️ Работа с графикой, контентом и шрифтами

- **Процессор контента на Node.js (`content-processor.js`):** Реализован концепт Data-Driven. Разработчик пишет статьи в папке контента в форматах Markdown (`.md`) или Microsoft Word (`.docx`). Кастомный асинхронный процессор на лету конвертирует файлы, очищает мусорные теги Word, выстраивает иерархию заголовков H1/H2 и нативно инклудит мастер-шаблон.
- **Smart WebP Cache & SVG Спрайты:** Автоматическая генерация `.webp`. Плагин `newer` сопоставляет базовые имена файлов, благодаря чему картинки не пережимаются заново при перезапуске сервера. SVG-иконки нативно очищаются от лишних атрибутов через SVGO-трансформатор во время сборки в спрайт.
- **PWA Favicons:** Автоматическая генерация полного адаптивного набора иконок (Apple, Android, браузеры) и манифестов из одного файла `favicon.png`.
- **Авто-шрифты:** Сборщик автоматически конвертирует исходные `.ttf`/`.otf` файлы в облегченный формат `.woff2` и сам генерирует файл подключения `_fonts.scss` со всеми начертаниями и поддержкой `font-display: swap`.

### 🗺️ Архитектура, Системные Алиасы и Роутинг

Для чистых импортов без бесконечных цепочек `../../` настроены системные алиасы путей в `tsconfig.json` и Webpack:

- `@/*` — указывает на корень скриптов `src/js/`
- `@comp/*` — указывает на папку компонентов `src/components/`
- `@modules/*` — указывает на папку логических модулей `src/js/modules/`
- `@plugins/*` — папка `src/js/plugins/` для кастомных локальных библиотек

**Кросс-страничный роутинг без ошибок Cannot GET:** Локальный сервер BrowserSync перенастроен с базового пути `@file` на виртуальный роутинг репозитория (`/portfolio/`). Это полностью ликвидировало проблему многостраничной вложенности: якорные ссылки, плавный скролл и переходы между статьями блога и главной страницей работают безбагово как на локальном компьютере, так и на серверах GitHub Pages.
